**v0.1.13 — since v0.1.12**

Most of this release is about books InkDrop had already found, already downloaded, and then refused — for reasons that turned out not to be about the book at all.

**Fixed**

- **Files that were already downloaded were being refused as damaged, without ever being opened.** Any archive whose images added up to more than 512 MB skipped image validation completely, and the empty result was then recorded as "invalid image payload" — a verdict about the file, from a check that never ran. Every archive ever refused this way here was a valid file: 8 of 8, across three different series, all of them intact. Large archives are now sampled instead — a bounded selection of pages spread across the archive, always including the first and last. An archive that fails that sample is still refused.
- **A folder name was being read as an issue number.** For a file like `Spawn (1992) Volume 01 Issue 169.cbz`, the `01` from `Volume 01` was compared against issue `169` and the file turned down as a mismatch. 39 staged files across three series were affected, and Manual Review was showing seven of them at once. Worth being straight about the size of this one: every affected issue already had a copy in the library, so what this cost was Manual Review noise and repeated re-downloading, not missing books.
- **A transfer that didn't finish was recorded as a file that is wrong, forever.** A Soulseek transfer that stalled, failed, or lost its staged file marked that exact candidate unusable permanently — none of which says anything about whether the file was right. Those outcomes now use the same 30-minute retry window that already applied to the same reasons elsewhere. 170 candidates on books you are still missing were released by this. That means they are allowed to be tried again; it does not mean they will download.
- **The daily library reconciliation report was printing into the container log.** Series titles, filenames, library paths and the database path were being written to ordinary Docker logs every day, alongside the private copy they were meant to go to. The log now gets counts only. Failures are still reported, and still say why.
- **InkDrop could not reliably say which version it was running.** Deployment identity is now resolved on its own surface and fails closed on an undeclared value, instead of different screens answering differently.
- **The mobile shell was stating things about state it could not support.** Those claims are gone.
- **Two Manual Review decisions could run at once in the same tab.** A second choice is now refused while the first is still running, rather than being sent alongside it, and the panel says so while it is working.
- **The System page now reports real backup status**, and the backup cadence is a setting rather than a fixed value.
- **Typing in the sidebar series search could land on a full-page "this series may have been removed" error** — for a series that was on screen and had not been removed.
- **The Settings toolbar read as a floating strip** with no page header above it.

**Needs a decision from you**

- **The collected-edition preference now reaches the matcher, and nothing is set.** Until this release a stored preference never reached the acquisition path at all, so the shipped default decided every case. It reaches it now on the main acquisition and replay paths. Two things to be straight about: the Soulseek probe path still uses the shipped default rather than your setting, and no value is stored anyway — so nothing changes until you choose one. It matters for books like Goodnight Punpun, where three sources offer the same seven-volume omnibus and only one of them labels it as an omnibus.

**One thing to know**

- Files already marked as "invalid image payload" before this release are not re-examined the moment you upgrade. The staging scan remembers its decision about a file for seven days, so those files come back into consideration as the records expire. There is nothing you need to do.

**Correction to 0.1.12**

0.1.12 was the release whose job was to stop screens telling you things that weren't true. Four of its own claims did not hold up.

- **"2,232 perfectly good matches across 313 books" was not proved.** That number counted repeated diagnostic summary rows, not a set of independently verified good files. The genuinely-good subset cannot be reconstructed from the evidence we published.
- **"Mobile Home replaces the active-client display with a Series rail" was false as written.** The rail did ship. But the same screen still labels a seven-state aggregate — queued, searching, downloading, importing, needs-attention, failed and blocked — as "Active downloads".
- **"The reconciliation report only reports and never deletes" was too broad.** It never deletes library files, and the report scan itself is read-only. But the feature also exposes an explicit repair that updates ledger flags. The claim was true of the report and not true of the feature.
- **The backup result was one experiment, not a guarantee — and the real finding is worse.** "1.17 GB and 221,969 writes with nothing missing or corrupted" described a single bounded test. Since then a real scheduled archive was restored, and **a restore can report success while leaving the instance in a mixed state.** That archive predates completion-ledger backup, so the restore returned success with the completion database not restored, left a newer completion database in place, did not snapshot it, and said nothing about any of that. What the test did prove is that the data restores. It did not prove a working instance: no restored web or worker was ever started.

**What we left out**

Because of those four, every bullet above had to be checkable against the shipped build or against real data. Several did not survive that, and were cut rather than written carefully:

- Internal CI and packaging changes shipped in this release. Real work, nothing you can see.
- Any claim about how much of your backlog these fixes will clear. We know what was unblocked. We do not know what will download.
- Any restated measurement we could not re-derive.

If a bullet here reads smaller than the fix sounds, that is deliberate.
