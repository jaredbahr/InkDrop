Notifications, SLSKD search-quality fixes, and a security hardening pass this build.

- Notifications are now a real system instead of a simple on/off toggle: choose which events each channel (Discord, Pushover) announces, scope a channel to specific series, set quiet hours so non-urgent alerts wait until morning, see a delivery history of what actually went out, and test a webhook or token before relying on it. Fixed a few cases where a notification should have fired but silently didn't, including Pushover's token and user key sometimes failing to save.
- SLSKD searches use better search terms: no more literal "cbz"/"cbr" keywords that missed matching files in the other format or pulled in unrelated audio releases, plus a couple of new query variations for titles where singular vs. plural makes a real difference in what turns up.
- SLSKD searches also get more time to come back before InkDrop assumes one timed out and starts over.
- Fixed several specific stuck-download patterns: a candidate that keeps getting found and rejected now gets flagged for you to decide on instead of looping forever, a single timeout no longer permanently blocks a source, and a search that only turns up already-rejected results now rotates to a different search term instead of parking indefinitely.
- Fixed downloads that were found and grabbed but never finished landing in your library.
- Downloads that were only waiting on a rate-limited or temporarily unavailable source no longer get mislabeled as failed transfers.
- The "item imported" notification no longer repeats for the same file on every re-check — you'll get it once.
- Provider API keys and webhook tokens no longer show up in error messages or diagnostic output.
- Smaller fixes: Recover Missing's tiles no longer overlap and Search All's scope is clearer; SLSKD's default per-user transfer cap was raised (4 to 8, up to a ceiling of 20) so a single well-stocked source doesn't get throttled as quickly.
