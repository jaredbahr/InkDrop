**v0.1.14 — since v0.1.13**

Most of this release is InkDrop correcting things it had told you. A book whose file was gone still counted as owned. A check that failed to run reported the file as bad. A repair that was attempted was counted as made. None of those were wrong about the library; they were wrong about themselves.

**Fixed**

- **A book whose file you deleted stayed marked as owned, permanently.** InkDrop notices a managed file has gone, marks it missing and puts the book back on the wanted list — but that release only ever ran on the single pass that first noticed. If that pass did not reach it, every later pass gave up in the same place and the book stayed "owned" no matter how many times the check ran. It is now released on every pass, so a book left stuck in that state returns to the wanted list and can be searched for again — however long it has been sitting there.
- **One unusual folder layout could stall the daily integrity check entirely.** When a series folder is consolidated, the check moves its record to the new location. If another record already claimed that file, the move failed and the whole check stopped — and because it runs first, two further checks behind it never ran at all. It now refuses that single move, records what it found for you to look at, and carries on.
- **Manual Review did not say what it was expecting.** A refused import showed a reason code and left you to work out the rest. It now states the series and issue it wanted, the file that actually arrived, and why they disagree. When it cannot tell, it says so rather than showing empty fields.
- **An archive integrity check reported its own failure as the file's.** If the check could not run, the file was recorded as bad. A check that did not happen is not a verdict, and it no longer produces one.
- **The metadata guard counted repairs it attempted as repairs it made.** It now reports only what actually changed.
- **A scan result whose freshness could not be checked was reported as fresh.** It now says the freshness is unknown, which is a different thing.
- **A download-client credential was only read from one place.** If yours lived anywhere else, InkDrop behaved as though it were missing. It now looks where the credential actually is.
- **The mobile home screen counted your library wrongly**, and showed a diagnostic meant for the desktop.
- **InkDrop now refuses to open a state database written by a newer version of itself.** Previously an older build would migrate a newer database backwards and rewrite its version number, leaving nothing to show it had happened. This matters if you ever roll back an image.

**One thing to know**

- **Stack traces in your container log are usually not a crash.** When InkDrop turns down a request because something about it was invalid — a value a form would not accept, an id that no longer exists — it writes a full stack trace next to the refusal. It looks identical to a genuine fault and it is not one. Nothing is broken and there is nothing for you to do. The groundwork to print a single line for refusals, and keep the stack for real faults, is in this release; the change becomes visible as each part of the API is converted over.

**Known gaps**

- **There is no way to retract a published release.** If a release goes out and is later found to be wrong, nothing in the tooling can un-publish it. Verified across every workflow and tool in this repo.
- **The public source export does not record which private commit produced it.** The manifest lists every file and its size but no source revision, so a published tag cannot be traced back to the exact state it was built from.
