**v0.1.12 — since v0.1.11**

Most of this release is us fixing things InkDrop was telling you that weren't true. If you've had books sitting in Wanted or Queue for weeks, this one's worth taking.

**Fixed**

- **"No source found yet" was hiding the real answer.** 2,118 items across 186 series were sitting under it — and every single one *had* been searched. Wanted now tells you what actually happened: we found something and turned it down, we found something and it's waiting on you, the search never finished, or we looked and there genuinely wasn't anything.
- **Five reasons searches were quietly missing things.** We were asking for `Injustice 2 6` when the site only answers to `Injustice 2 006`. Manga searches were sending the wrong year and dropping the volume marker, so `Chainsaw Man 24 2019` came back with 32 anime videos. A perfectly good match was refused 2,232 times across 313 books — including `Dorohedoro Vol. 16` — over missing volume info. And a year in the title got read as an issue number, so `Uncanny X-Men 1963 001` went looking for issue 1963.
- **Downloads that finished weeks ago could sit on "Importing" forever.** Two bits of cleanup code were handing the same items back and forth. 54 books were stuck this way, some for a fortnight — and they were eating about one in five Soulseek attempts while they sat there.
- **"Actively processing" wasn't.** 49 imports stuck for up to 47 days were showing green. That page now checks whether anything is actually happening before it says so.
- **Old alerts were being deleted while still in use.** Notification history now keeps what the app still needs.
- **Tapping "Search now" could fail with an error instead of starting a search.** It happened when a search was already running in the background, and it hit new installs hardest — the check it tripped over depends on a file that a fresh install doesn't have yet. It searches now.
- **Mobile Home was showing a download-client list that was wrong twice over.** Ten rows claimed 1,639 things were "active" — at that moment, exactly one file was downloading. And only three of those rows were download clients at all; one was literally called "Download Client". It's now a rail of your own series, where every number counts something real and nothing claims to be "active". One rough edge we're leaving for now: the series that needs you isn't always sorted first.

**Changed**

- **"Compare & Merge" is now just Compare.** On real libraries, 21 of 24 duplicate groups had identical titles — so the button asking you to pick a keeper couldn't tell them apart either. It shows you the differences; it doesn't merge anything on its own.
- **New report showing where your library and your database disagree** — files on disk InkDrop doesn't know about, entries pointing at files that aren't there, duplicate issue numbers, books stranded by a folder rename. It only reports. It never deletes.
- **Queue Details was still leaking file paths and download IDs on some screens.** Now it doesn't.

**Verified**

- **Backups don't tear if you're mid-download.** We ran a backup of a 1.17 GB library through 221,969 writes and it came out clean — nothing missing, nothing corrupted. **One thing to know: restoring doesn't bring your passwords and API keys back.** You'll re-enter those.

**Correction to 0.1.11**

- The last release notes said every screen hid file paths and download IDs the way the Queue does. That wasn't true when we published it — four of them were still showing real values, three on the Queue page itself. We've corrected that note, and it's genuinely fixed now.
- They also said a Soulseek transfer that finished weeks ago was no longer replayed as if it had just landed. That one shipped, but it never actually ran, so nothing changed for you at the time. It runs now.
