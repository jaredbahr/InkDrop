# InkDrop 0.1.0-beta.1 — Opening a series page no longer risks a minute-long hang

Almost every series page could take over a minute to open, or fail outright, if its stored description was empty — 338 of 342 series on the build this was found against. Traced to a database write that ran on the request itself and could wait out a full 60-second lock timeout before failing loudly. The description now loads immediately and that write finishes on its own thread, in the background, where it can't hold a page open.

- A series with no cached description used to run its refresh inline and could wait out a 60-second lock before failing; it now serves the fetched description right away and finishes the write in the background.
- Leaving System or Settings and going anywhere else could leave that page's row list stuck invisible, even though the data underneath was loading and rendering correctly the whole time. Every page now shows its rows correctly regardless of where you came from.
- The cold summary rebuild that runs after a stretch of inactivity is about 21% faster end to end.
- Downloads that never actually started transferring could sit forever without being retried. A separate 24-hour timeout, adjustable in Settings, now releases them for a real retry — distinct from the existing 45-minute check for downloads that did start moving and then stalled.
- A Manual Search run that lost its worker mid-search (a container restart, for example) would retry automatically — but the retry was guaranteed to fail instantly, reporting "Provider Timeout" with zero real work done. It now gets a genuine second attempt.
- Starting a Recover Missing pass could fail silently under database contention with no visible error, and Pausing one could silently do nothing. Both now report what actually happened.

This is the first build meant for people outside internal testing. If something doesn't behave as expected, see "Reporting a problem" in the README.
