# InkDrop 0.1.0-beta.2 — First-run setup works

Creating the administrator account on a fresh install returned "Forbidden" and there was no way past it from a browser. The server expected a setup code written to a file in the config directory, but the setup screen had no field to send one, so the two could never agree. Nobody could finish setting up a new install.

Whoever opens InkDrop first now creates the administrator account directly, which is how most self-hosted apps do it. The setup screen closes for good once that account exists, and two people hitting it at the same moment cannot both succeed. Keep the port on your own network until setup is done, since anyone who can reach it before you can claim the install.

- The published install instructions mounted libraries and downloads at paths InkDrop does not read, so a new install showed an empty library and staged downloads outside any mount. The compose example now uses `/data/comics`, `/data/manga`, and `/downloads`, and a test derives those from the image itself so the two cannot drift apart again.
- The image's source label pointed at a repository nobody outside the project can open. It now points at this one.
- Repository layout: test and audit scripts moved into `tests/`, cron and maintenance scripts into `scripts/`, and the optional compose overrides into `deploy/`.

If you installed with the earlier instructions, your libraries are mounted where InkDrop never looks. Either update the mounts to match the current README, or point Comic root and Manga root under Settings, Media Management at wherever you already mounted them.
