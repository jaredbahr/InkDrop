## InkDrop 0.1.17

Most of this release is about the Manual Review queue and the books that kept
landing in it. Files that had already been downloaded, correctly, were being
held for a decision — sometimes the same file every hour — because the check
that refused them could not say what it wanted, and nothing ever retired the
row once the question stopped making sense.

**If your review queue has rows you do not recognise, take this one.**

**The review queue**

- **A review row now says which check refused the file.** The reason was being
  read out of the record and then dropped before the row reached either the
  table or the mobile list, so every row read as "automation gave up" whatever
  had actually happened. Of 237 active rows on a pinned snapshot, none carried
  a reason a reader could see.
- **Rows about files that cannot be anything you still want now retire
  themselves.** A weak filename with no unit behind it — a bare number, a
  title with a stray id after it — had no way out of the queue: the retirement
  path needed a unit, and these rows had none. 55 such rows were sitting there,
  none of them a question anyone could answer.
- **A review row is retired on the file, not on a memory of it.** The old check
  asked a scan table whether the unit was present and never went to disk, so a
  row could be closed on stale metadata while the file it asked about was gone.

**Getting the right book**

- **A one-issue work grabbed from Soulseek is judged by the same proof once it
  lands.** Before the download, a series the catalog proves has exactly one
  issue carried that proof; after the transfer, the staged file was judged
  without it. The copy was marked bad, another was fetched from someone else,
  and the first became a review row — seven copies of one book, in one case.
- **A file named only for its work is imported as that work's single issue.**
  The exemption that covers this shape already existed, but it only ran once a
  number had been parsed off the filename, which is exactly what these files do
  not have. 25 rows were waiting on it.

**Downloads and clients**

- **A download sitting at 0% is no longer treated as slow.** It was given the
  same twelve-hour window as a transfer making progress, so the dominant
  failure shape waited about eleven hours of dead time before anything else was
  tried. Replayed over the attempts that were actually retired on a pinned
  snapshot, 39 would have been caught sooner.
- **A fault inside InkDrop is no longer reported as the download client being
  down.** The poll wrapped its whole body in one catch that returned
  "client unavailable", so an error in InkDrop's own code came back as a
  statement about the client — on every pass, with nothing downstream able to
  tell the two apart.

**Your library**

- **A second copy of a book already on the shelf binds to its own series and
  unit.** The import could attach to the wrong record, and the queue was marked
  verified before the import row existed, so a new import could not prove
  itself in the pass that created it.
- **A library folder can be given to the series that should own it.** Two
  records claimed one folder — an unmonitored print edition held the lock while
  the edition being collected went without — and the two writers that assign
  these are both automatic, so there was no way to say which was right.

